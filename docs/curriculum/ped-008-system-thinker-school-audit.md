## Concrete teaching changes

1. **Executable XML namespaces**: The teaching body now includes a complete Python 3 program operating on two equivalent namespace prefixes, a wrong URI and malformed XML. Expected results: identical Service names, `ValueError`, `ParseError`. Distinguishes parsing, namespace identity and domain-required fields; no untrusted-XML security assurance implied.
2. **Executable XSD**: A complete lxml schema and four documents distinguish valid input, wrong datatype, missing required child and wrong target namespace. Expected Booleans: true/false/false/false, with actual validator diagnostics displayed.
3. **Executable file-batch handoff**: The enterprise contract lesson now runs Python 3 with a same-filesystem `.part` → final rename and an SQLite delivery ID/checksum ledger. Expected events: not ready, accepted, duplicate after restarting the consumer, conflicting replay and rejection of invalid content. The complete Python example was run in a disposable environment; this is not a real FTP/SFTP or Steward end-to-end test. `scripts/check-system-thinker-file-handoff-teaching-example.mjs` extracts the exact published code as a regression.
4. **Source-extracted XML/XSD regression**: `scripts/check-system-thinker-xml-teaching-examples.mjs` reads the exact published learner code rather than a copied standalone fixture. Registered in `scripts/tests/curriculum-smoke.test.mjs`. CI installs lxml and includes this branch. CI passing must be checked against the latest SHA.
5. **Staged distributed labs**: A 300-minute combined practical was replaced by four lessons: Redis cache-aside and outage; RabbitMQ consumer/ack/replay; PostgreSQL transactional outbox/order/restart; cross-module Steward defence. Each distinguishes setup, expected observation, negative experiment, durable artifact and what remains unverified. Local commands are deliberately loopback-bound and not production recipes.

6. **Independent transfer assessment**: The System Thinker milestone now asks for a novel university booking system with conflicting and failure requirements. The reviewer must score problem/evidence, boundaries, invariant/concurrency, CSV/SOAP contracts, asynchronous trade-offs and uncoached defence (each 0–2, pass at least 10/12 without any zero).
