## First remediation checkpoint: Kubernetes foundations

**Evidence from actual authored reading:** `cloud-kubernetes-foundations-worked.ts` supplies targeted new sections for all sixteen existing concept lessons, not a generic appendix. It establishes vocabulary and boundaries before commands, an isolated `kind-tsa-ped005` context, a complete two-replica nonproduction Deployment, readiness/resource declarations, a controlled Pod-replacement observation, a separately declared Service with selected endpoints and a deliberately empty-selector Service. It explains why the Nginx image tag is not an approved immutable Steward artifact and why reconciliation does not imply application health or genuine node-failure high availability.

**Source validator (expanded to all sixteen concept lessons):** `scripts/check-cloud-k8s-lesson-source.mjs` extracts the exact published YAML, parses it using Python/PyYAML, checks Deployment selector-to-template labels, readiness, resources, replica count, healthy/empty Service selectors, intentionally unschedulable Pod, unbound PVC, deliberately failing readiness probe, namespaced RBAC allow-only rules and an illustrative OpenShift Route. It does not execute any cluster. This checks a teaching fixture and its wiring, **not a running Kubernetes cluster**.

**Wrapper correction school-wide:** the Cloud entrypoint now exposes only actual authored lessons for **all 11 paths**. `scripts/check-resolved-practical-contracts.mjs` requires real reading/practical coverage across all 11, rejects generated models/preparations, and requires the 16 original Kubernetes concept readings plus their practical and transfer reflection. Original authored IDs remain unchanged; removal of artificial wrapper activity IDs changes the displayed activity count and must be checked for learner-progress/re-entry effects.

**Required next steps:** validate the rendered lesson sequence and execute the safe kind labs, then verify true OpenShift-only behavior in an authorized disposable cluster, and complete independent learner validation for each Cloud module in actual learner order. ### School-wide source remediation and test boundaries — paths 2, 5, 7 and 10

The VPS practical quality adapter previously **overrode** the safe, read-only OS inspection with a `sudo dnf upgrade --refresh` command. This could modify a learner's real VPS without a prior maintenance checkpoint. The `alignRockyLinux` override was deleted; the original source lesson differentiates Ubuntu/apt from Rocky/DNF and explicitly warns that DNF check-update status 100 can mean updates are available rather than a fatal failure.

All **12 original Cloud Building Blocks** readings now have domain-specific worked mechanisms, failure/transfer cases and correct service boundary comparisons, through `cloud-building-blocks-source-depth.ts`. The local Python CIDR experiment checks /16 containment, non-overlap of /24 subnets and address classification; it does not operate real network security controls.

Five vulnerable original IaC readings now add a standalone providerless `terraform_data` exercise (requires installed OpenTofu CLI) that creates a unique temporary directory, initializes with no cloud backend, validates, saves and inspects a plan, applies the exact saved plan, checks no-change and destroys a local training object. The tutorial is deliberately **UNVERIFIED for actual OpenTofu CLI execution**; automated checks inspect its source and safety properties, not infrastructure.

Six original Cloud Architecture and Cost readings now cover SLO unavailability budgets, backup RPO/RTO and restore ordering, correlated failure, complete monthly unit pricing, orphaned resource cost and right-sizing. The published Python models use **explicitly fictional** dollar prices and a hypothetical 730-hour month. They are neither current provider offers nor measured Steward availability. Exact local Python output is executed in CI.

`scripts/check-cloud-building-block-depth.mjs` verifies original-reading integration, all 12 topic definitions, 5 IaC contracts, 6 architecture cases, the exact CIDR/cost/SLO Python code, absence of the destructive VPS overlay and absence of shallow generated wrapper pages.
